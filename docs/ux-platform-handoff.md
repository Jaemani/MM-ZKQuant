# 통합 투자·운용 UX

## 화면과 인증

홈 `/`, 전략 탐색 `/strategies`, 공개 상세 `/strategies/:slug`, 내 자산 `/assets`, 내 전략 `/manage`, 신규 전략 `/manage/new`, 프로필 `/manage/profile`, API 연동 `/manage/api`, 소유 전략 관리 `/manage/:id`를 실제 URL로 제공합니다. Vercel은 `/api`와 정적 자산 이외의 경로를 SPA로 처리합니다.

공통 로그인은 지갑 서명 세션입니다. 한 계정으로 투자와 운용을 모두 사용합니다. 기존 투자자 세션을 복원하며 계정/네트워크 변경과 세션 만료 시 개인 화면을 비웁니다. 개인 자산은 추가 지갑 서명 후 브라우저와 TEE 사이의 암호화 요청으로 조회합니다. 조회 전 수치를 0으로 대신 표시하지 않습니다.

## 투자와 운용

전략 상세의 투자 패널에서 금액·성과보수·정산 일정을 확인한 뒤 승인·입금·TEE 반영을 진행합니다. 입금 성공은 다음 목표 제출 대기 상태입니다. 거래 해시를 저장한 뒤에는 재입금을 막고 기존 거래의 반영을 이어갑니다. 출금 요청액은 평가액에 중복 합산하지 않습니다.

전략 등록은 공개 프로필, 전략 소개, 운용 조건, 최종 확인 단계입니다. 등록 후 전략별 개요·목표 제출·실행 내역·운용 조건·API 연동 화면을 사용합니다. 웹에서는 로그인 세션으로 운용하고 기존 외부 프로그램의 API 토큰은 계속 지원합니다. 토큰 평문은 발급 직후에만 보여 주며 목록에는 접두사와 사용 시각만 표시합니다.

목표는 전체 벡터를 교체합니다. 생략 또는 0%는 포지션 정리, 음수는 숏입니다. 접수·실행 확인·완료·부분 체결·실패를 구분합니다. 상태 조회는 로그인·TEE 설정 준비 후 시작하며 10초 간격입니다. 미확정 거래는 같은 요청의 재제출을 유도하지 않습니다.

## 차트와 API

공개 상세의 `period=1d|7d|30d|all`이 실제 성과·자기자본 이력을 반환합니다. 기간별 버킷과 양 끝 관측값을 유지하며 전체 기간은 최대 약 900개 버킷으로 샘플링합니다. 관측되지 않은 기간은 생성하지 않습니다. 동일 기간 비교는 충분한 기록이 없으면 집계 전으로 표시합니다. 개인 누적 손익은 `운용 평가액 + 대기 자금 + 지급 완료액 - 누적 입금액`입니다.

- `GET /v1/me`: 공개 전략가 프로필 추가.
- `GET /v1/api-keys`: 본인 토큰 메타데이터 조회.
- `POST /v1/api-keys/:id/revoke`: 본인 토큰 폐기.
- 기존 전략 생성·설정 변경·소유권 확인은 로그인 세션과 API 토큰을 지원.
- 암호화 전략 요청에 `sessionToken`을 추가하고 기존 `apiKey`를 지원.
- 암호화 본인 포트폴리오 응답에 `deposited` 추가.

공개 API의 성과는 TEE 집계이며 ZK 검증 성과가 아닙니다. 단일 Vault, 전략별 독립 실행과 비공개 장부 경계는 유지합니다. 전략별 전체 운용금액, 투자자별 지분, 목표, 실행 계정 연결을 공개하지 않습니다.

웹의 비공개 조회·주문은 `/api/tee/encrypted-investments`와 `/api/tee/encrypted-strategy`를 통해 암호문만 중계합니다. 브라우저는 기존 TEE 공개키로 암호화하고 TEE 응답을 직접 복호화합니다. 중계 API는 DB를 사용하지 않으며 평문·토큰·장부를 해독하거나 기록하지 않습니다. Vercel 개별 배포 주소에서 Phala CORS가 막히던 문제를 방지합니다. 암호화 POST는 자동 재시도하지 않으며, 응답 지연 시 접수 여부를 먼저 조회하도록 안내합니다. 외부 프로그램의 TEE 직접 연결도 유지합니다.

공개·계정 정보의 GET 요청은 일시적인 네트워크/5xx 오류에 한 번 재시도합니다. 새로고침 시 계정 조회 장애만으로 저장된 세션을 삭제하지 않습니다. 서버가 401을 반환하거나 지갑·네트워크가 바뀌면 기존처럼 세션과 개인 화면을 초기화합니다.

## 검증

`npm test`는 현재 플랫폼의 핵심 28개만 실행합니다. 변경한 기능의 테스트를 우선 실행하고, 화면 변경은 `npm run build`와 해당 화면·흐름을 확인합니다. 컨트랙트 변경에는 `npm run test:contracts`, 이전 연구·프로토콜 검증까지 포함하는 전체 확인에는 `npm run test:all`을 사용합니다.

`scripts/platform-ux-browser.mjs`는 여러 화면에 걸친 흐름을 변경할 때 탐색·검색·필터·비교·URL 재접속·공통 로그인·자산 조회·모바일 폭을 확인하는 용도입니다. 브라우저 스크립트는 `.data/platform-live/e2e.json`의 테스트 지갑을 Node 측에서 사용하며 키를 브라우저에 보내지 않습니다. 기본 브라우저 검증은 거래 전송을 차단합니다.

`scripts/platform-ux-transact.mjs`는 별도의 실제 테스트넷 거래 검증입니다. 명시적인 테스트 전략을 등록하고 자기자본/투자자 입금, 목표 제출, 실행, 출금 요청·취소·재신청을 수행합니다. `--fund`는 기존 테스트 지갑에 테스트 MON/AUSD를 보충합니다. 일반 화면 확인 용도로 실행하지 않습니다. 검증 기록과 캡처는 무시되는 `.data/ux-review`에 저장합니다.

배포는 기존 Vercel `mm-zkquant`, Supabase `monad`, Phala CVM을 사용합니다. 이번 UX 확장에 신규 테이블 또는 컨트랙트 배포는 필요하지 않습니다. Phala 업데이트 시 기존 identity와 상태 볼륨을 유지합니다.

Vercel의 `DATABASE_URL`은 같은 Supabase 프로젝트의 트랜잭션 풀러(6543)를 사용하고 함수당 pg 연결을 1개로 제한합니다. 로컬 `.env`의 세션 풀러(5432)는 지속 실행 및 마이그레이션용으로 유지합니다. API는 이름 있는 prepared statement나 세션 상태를 사용하지 않으며 트랜잭션은 한 client의 BEGIN/COMMIT으로 묶습니다. 참고: [Supabase 연결 가이드](https://supabase.com/docs/guides/database/connecting-to-postgres).

- 배포 사이트에서 검색·필터·최대 3개 비교·상세 링크 재접속, 공통 로그인·복원·계정 변경 초기화, 비공개 자산 조회, 모바일 가로 넘침 없음 확인.
- 실제 테스트 전략 등록, 자기자본 110 AUSD와 투자자 20 AUSD 입금, 목표 제출·실행 완료, 출금 신청·취소·재신청 검증.
- 예정 정산에 투자자 지급 19.998112 AUSD, 잔여 지분 0, ERC20 Transfer 수신자·금액 검증. 거래: `0xd990409b10d7e64be74e0432bcafe06e88d21a5108b51cd01393d5d897a1252f`.
- 웹의 운용 조건 변경 비교·사전 공지와 공개 상세 변경 예고 확인. 세션 기반 소유권 확인, 토큰 발급·목록의 비밀 필드 미노출·폐기 후 요청 거절 확인.

## 2026-10-05 연결 오류 수정 검증

- 개별 Vercel 배포 주소에서 Phala preflight에 허용 Origin이 없어 `Failed to fetch`가 발생하는 것을 Chromium으로 재현했습니다.
- 암호문 중계와 조회 재시도 적용 후 전체 459개 테스트 통과. 최종 DB 설정 변경 후 관련 7개 테스트 재확인.
- 새 배포 주소에서 브라우저의 Phala 직접 연결을 차단해도 전략가·투자자 로그인, 비공개 자산 조회, 실행 내역, 새로고침 복원 성공. 계정 조회에 503을 한 번 주입해 자동 재조회와 로그인 유지 확인.
- 고정 도메인의 설정·목록·실적 상세 API를 세 차례 병렬 조회해 9개 응답 모두 200 확인.
- 실제 TEE의 주문 접수 경로에 잘못된 시퀀스를 보낸 결과 `SEQUENCE_MISMATCH`가 암호화 응답으로 반환됨을 확인. 검증 전후 주문 수와 시퀀스 동일. 이번 연결 검증에서 신규 거래를 실행하지 않았습니다.
