## 통과한 ZK 실험의 범위

운용자 서명이 맞아도 잘못된 Book 장부 변경은 거부됨을 실제 회로·Solidity verifier·외부 DEX 포크로 검사했습니다. [재현 절차와 한계](zk-transition-runbook.md), [실행 기록](evidence/zk-book-fork.json), [독립 검증](evidence/zk-book-verification.json)을 함께 봅니다.

- 두 Book의 현금·자산·예약 금액·운용자 제출 순서·공개키를 비공개 상태에 포함합니다.
- 운용자 서명 확인, 자금 예약, 실제 체결에 따른 정산을 나눕니다.
- 다른 Book으로 자산을 옮기면서 전체 합계만 맞추는 반례를 검사합니다.
- 실제 수령량은 Vault가 거래 전후 잔액으로 확인합니다. 임의 수치로 만든 proof도 실제 실행 기록과 다르면 정산하지 않습니다.
- 별도 Phala TDX 실험에서 암호화한 합성 witness로 실제 proof를 생성하고 로컬에서 검증했습니다(4,917ms). 이 proof가 DEX 포크 거래를 구동한 것은 아닙니다. [TEE 실험](tee-hardware-probe.md).

검증된 회로는 전체 프로토콜 완성이 아닙니다. 최초 Book 배정은 신뢰된 테스트 초기 상태이며 투자자 지분 증명이 아닙니다. 연구용 운용자 서명 키는 기존 지갑 등록과 아직 연결하지 않았습니다. 목표 포지션에서 주문을 계산하는 증명도 이후 작업입니다.

로컬 단독 Groth16 setup은 연구용입니다. 실자금 검증키로 사용하지 않습니다. 연구용 Vault는 chain ID 31337에서만 배포되도록 제한합니다.

## 필요한 결정과 결과 기록

현재 코드·문서 작업에는 추가 정보가 필요하지 않습니다. 첫 TEE 실험의 후불 해제와 최대 $2 사용은 승인받았습니다. 새 API/배포 권한이 필요하면 목적과 범위를 구체적으로 확인합니다. 키를 채팅이나 저장소로 전달하지 않습니다.

경제조건 미정 목록과 인수 기준은 [팀 개발명세](team-development.md)를 따릅니다. 새 검사 성공 전에는 PASS로 표시하지 않습니다. 환경·체인·코드/회로 버전·실 하드웨어 여부·외부 송신 여부를 기록합니다. 기존 109개 회귀 테스트와 외부 포크 16개 검사는 새 명세 인수와 합치지 않습니다.

## 바로 이어서 할 일

1. 현재 회로의 암호화된 주문 입력을 TEE에서 생성·보관하는 장부에 연결하고, TEE proof → Vault 실행 → receipt → TEE 정산을 한 시험으로 묶습니다. 운영 이미지·OS·KMS 승인도 별도로 완료해야 합니다.
2. 목표 포지션 intent에서 주문을 계산하는 규칙과 운용자 지갑 등록을 연결합니다.
3. 입출금·투자자 지분·가격 출처·자기자본 잠금을 별도 상태 전이로 확장합니다.
4. 팀이 경제조건을 확정하면 성과 staking·보수를 구현하고, 복구·최종 환매와 도메인별 증거 화면을 연결합니다.

이 단계들 없이 이번 실험 결과를 서비스 출시 승인으로 사용하지 않습니다.

최신 회귀 실행: 111개 테스트 통과, 프런트엔드 build 통과. production 의존성 감사 0건, 연구용 TEE probe 의존성 감사 0건. ZK 개발 의존성에는 기존 elliptic 경로의 low 등급 취약점이 남아 있으므로 운영 준비 완료로 표시하지 않습니다.
