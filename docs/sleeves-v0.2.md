# v0.2 구현과 검증 — 여러 전략, 하나의 공동 Vault

투자자가 고르는 상품은 개별 전략이다. Vault 전체 지분을 발행하지 않는다. 자산 보관과 실행 주소만 공유하고, 자본·지분·주문·체결·비용·손익·제공자 보수를 전략별로 귀속한다.

## 이번 구현의 실제 경로

1. 제공자가 지갑으로 `REGISTER` 요청을 서명해 독립 전략을 만든다. 한 지갑에 여러 전략을 등록할 수 있다.
2. 투자자는 전략과 금액을 명시한 `ALLOCATE` 요청을 서명한다. 외부 지갑 경로에서는 요청을 먼저 준비해 장부 변경을 잠근 뒤, 투자자 지갑이 ERC20 승인과 Vault 예치를 직접 전송한다. 서비스는 정확한 송신자·Vault·금액·요청 ID·성공 영수증을 확인한 뒤 그 전략의 units를 발행한다.
3. 해당 전략의 제공자가 자산·방향·금액을 서명한다. 서비스는 제공자 소유권, nonce, 만료, chainId, Vault 주소, 해당 전략의 가용 자본을 검사한다. 전략 alpha를 합성하거나 다른 전략 자본을 쓰지 않는다.
4. 서명한 비공개 요청의 해시를 Vault에 먼저 기록한다. 이후 블록에서 **같은 Vault**가 AMM 계약으로 매수·매도·차입매도·상환을 실행한다. 체인에는 strategyId나 provider ID를 보내지 않는다. TEE 미적용 상태에서 해시와 주문의 연결을 검사하는 주체는 운영자이며, 컨트랙트가 비공개 요청 전체를 검증하는 것은 아니다.
5. 장부는 가격 변화를 가정해 잔고를 만들지 않는다. Vault의 `Fill`, AMM의 `Swap`, 토큰 잔액, 실제 차입·담보에서 귀속 금액을 얻는다. AMM 수수료는 실제 체결에 이미 포함되므로 두 번 차감하지 않고 원래 수수료 자산/수량을 별도 기록한다.
6. 전략의 모든 포지션이 정산되면 해당 전략의 고점 초과 이익만으로 제공자 보수를 계산한다. 투자자는 자신이 가진 그 전략의 units만 환매한다. 보수 지급도 해당 전략의 미지급 보수 한도 안에서 실제 ERC20을 전송한다.

## 검증 결과와 증거

- `docs/evidence/omnibus-local.json`: Solidity를 실제 실행한 로컬 EVM 통합 경로.
- `docs/evidence/omnibus-testnet.json`: 새 Monad 테스트넷 계약의 전략별 11개 작업과 4개 사전 commitment 영수증. 운영자가 준비한 테스트 계정과 테스트 토큰을 사용했다.
- `docs/evidence/omnibus-rpc-verification.json`: 저장된 성공 여부만 신뢰하지 않고 RPC에서 영수증·로그·블록 해시·최종 확정 여부·바이트코드 해시·최종 현금을 다시 확인한 결과.
- `docs/evidence/omnibus-tests.txt`: 서명 위조, 다른 제공자 주문, 한도 초과, 재전송, 포지션 미정산 환매, 체결 귀속, 실제 출금 후 장애·재시작 복구, 외부 지갑 예치 준비/확정, 여러 전략의 동일 자산 차입 분리, 다중 자산 정산 등을 포함한 회귀 테스트.

테스트넷 Vault: `0xA39D15F83eC207c1868Be1D52771dfDb64b4b921`
테스트넷 AMM: `0x133dBb595232691D59514DB18569b04dc889EBA6`

100,000 tUSD의 상승 전략, 50,000 tUSD의 하락 전략, 30,000 tUSD의 현금 전략을 같은 Vault에 배정했다. AMM에 실제 테스트 토큰 거래를 넣은 뒤 정산했다. 상승 전략만 환매한 뒤에도 하락 전략과 현금 전략의 권리는 그대로였다. 보수 지급과 나머지 환매를 끝낸 최종 Vault 잔액·전략 권리·미지급 보수는 모두 0으로 일치했다.

이는 수익성 검증이 아니다. 통제된 시장 거래를 사용했으며, **전략별 귀속과 실제 자금 보존, 개별 환매**를 검증했다. 독립된 외부 참여자의 실전 성과를 증명하지 않는다.

## 보안·회계·복구 경계

- `VaultEquity = Σ StrategyEquity + ProtocolAccruals`와 `StrategyEquity = Σ InvestorClaim + ProviderAccrual`을 거래 후 검사한다. 현금뿐 아니라 현물 수량과 차입 lot의 담보/부채를 대조한다.
- units와 현금/토큰은 소수점 6자리 정수다. 개별 평가와 합산 평가 사이 반올림은 작은 상한을 검사해 별도 표시한다.
- 입출금은 해당 전략이 모두 정산된 때만 허용한다. 자산당 신규 주문/숏 담보는 그 전략 투자자 순자산의 25% 이내다. 같은 전략·자산에 중복 포지션을 추가하지 않는다. 서로 다른 전략은 같은 자산을 독립적으로 차입할 수 있다.
- 투자자 포트폴리오는 서명한 `VIEW` 요청에만 반환한다. URL의 투자자 이름만 바꿔 다른 지갑의 지분을 읽을 수 없다. 제공자와 투자자의 원문 요청은 비공개 로컬 파일에 저장한다.
- RPC 전송은 서명된 거래 bytes/nonce/hash를 먼저 디스크에 기록한다. 장부는 별도 pending intent를 먼저 기록한다. 체인 전송 후 장부 저장 전에 장애가 나면 같은 거래 해시를 재확인하고 한 번만 반영한다. 최종 확정되지 않은 거래는 완료 처리하지 않는다.
- 외부 지갑 예치를 준비하면 완료될 때까지 다른 변경을 막는다. 지갑 거절·탭 종료 후에는 같은 브라우저의 ‘미완료 예치 계속’으로 같은 요청을 재개한다. 임의 취소로 늦게 도착한 예치를 잃지 않게 자동 취소하지 않는다. 브라우저 저장소를 잃으면 운영자가 pending 요청과 체인 거래를 대조해 복구해야 한다.
- 지급불능·담보 부족·최종성 불명·대사 불일치에서는 중단한다. 다른 전략의 자금으로 손실을 충당하지 않는다. 자동 청산·보험·법적 파산 격리는 구현된 기능이 아니다.
- 한 데이터 디렉터리는 한 실행 프로세스만 사용한다. 프로세스 안에서는 쓰기와 조회를 직렬화한다. 다중 운영자 배포는 지원하지 않는다.

## 실행 방법

기본 검토 화면:

```sh
rtk npm run build
rtk npm start
```

`http://127.0.0.1:8790/`의 기본 조작은 **로컬 EVM과 공개된 테스트 키**를 쓴다. 이전의 단순 회계 시뮬레이터와 달리 실제 Solidity 계약의 토큰 교환·차입·상환·환매가 발생한다. 서버가 테스트 키로 서명을 만들기 때문에 이 모드는 실제 지갑 인증을 체험하는 모드는 아니다. 첫 시작과 재시작에는 계약 컴파일/거래 재생 시간이 필요하다.

외부 지갑 모드:

```sh
SLEEVE_NETWORK=monad-testnet rtk npm start
```

기존 서버를 종료한 뒤 실행한다. 새 v0.2 테스트넷 배포와 비공개 장부를 로드하며, 로컬 테스트 계정 서명 엔드포인트를 비활성화한다. 브라우저 지갑은 Monad 테스트넷(10143)이어야 한다. 사용자가 전략을 등록하고 자기 테스트 자금을 배정하려면 해당 지갑에 테스트 tUSD와 테스트 MON이 있어야 한다. 이 모드의 서비스는 여전히 localhost에만 바인딩한다. 지갑 연결 UI는 구현했으며, 자동화 검증은 서명 API와 외부 예치 어댑터 경로까지 수행했다. 특정 지갑 확장 프로그램의 승인 UI는 사람이 검토해야 한다.

```sh
rtk npm run prove:omnibus
rtk npm run verify:omnibus
rtk npm run test
```

테스트넷 증거를 재생성하는 명령은 `rtk npm run prove:omnibus:testnet`이다. `.data/omnibus-testnet-v02`의 기존 journal을 이어서 사용한다. 이전 PilotFund에 있던 자산은 새 경로에 사용하지 않는다.

## 아직 주장하지 않는 것

실운영 자산이나 외부 상용 DEX 연동, 독립 참여자의 forward 실적, 자동 청산 및 파산 처리, 다중 프로세스 운영, 운영자가 볼 수 없는 비밀성은 검증하지 않았다. AMM은 이 프로젝트가 배포한 테스트 토큰용 거래 계약이다. TEE·attestation은 사용자 요청대로 제외했다. 운영자는 비공개 장부를 읽을 수 있고 컨트랙트의 실행 권한을 갖는다. 공유 주소와 opaque ID만으로 시각·수량에 의한 통계적 추론까지 차단한다고 주장하지 않는다.

검토 가능한 산출물은 **서명·공동 보관·독립 전략 회계·실제 테스트 자산 거래·환매를 연결한 MVP**다. 상용 자금 운용 준비 완료라는 의미는 아니다.
